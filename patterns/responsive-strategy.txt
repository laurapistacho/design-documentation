11:Tdb7,# Responsive Strategy

ReviewPro is a desktop-first application with progressive adaptation to smaller screens. The mobile app is a separate product with its own patterns; this document covers the web platform.

## Breakpoints

| Token | Value | Name | Layout |
|-------|-------|------|--------|
| xs | 0px | Mobile | Single column, stacked, no sidebar |
| sm | 768px | Tablet | Simplified layout, collapsed sidebar |
| md | 980px | Small desktop | Full layout, sidebar collapsed by default |
| lg | 1440px | Desktop | Full layout, sidebar can expand |
| xl | 1920px | Wide | Max-width container, extra whitespace |

These are non-standard (not Tailwind defaults). Configure explicitly.

## Layout Behavior by Breakpoint

### >= lg (1440px) — Desktop

- Full admin shell (TopNav + SideNav expanded + Content)
- Data tables show all columns
- Multi-column forms (2-3 columns)
- Side panels / drawers appear alongside content (not overlay)

### md-lg (980-1440px) — Small Desktop

- Admin shell with collapsed SideNav (icon rail only)
- Data tables show priority columns, others accessible via "more"
- Forms: 2-column max
- Drawers overlay content (slide from right)

### sm-md (768-980px) — Tablet

- TopNav simplified (fewer selectors visible)
- SideNav collapsed, opens as overlay on tap
- Tables: fewer columns, horizontal scroll for complex tables
- Cards stack vertically
- Dialogs take more screen width

### < sm (768px) — Mobile Web

- TopNav: hamburger menu replaces sidebar
- Full-screen navigation drawer
- Single column everything
- Tables become card-based lists
- Dialogs become full-screen or bottom-sheet
- Filter bar becomes a single "Filters" button opening a panel

## Adaptation Patterns

### Content Priority (Tables)

Columns have priority levels. Lower-priority columns hide first:

| Priority | Example | Behavior below md |
|----------|---------|-------------------|
| 1 (critical) | Name, Status | Always visible |
| 2 (important) | Date, Score | Visible >= md |
| 3 (nice-to-have) | Source, Category | Visible >= lg |
| 4 (secondary) | Created by, Notes | Available via row expand |

### Cards & Tiles

- Desktop: grid layout (2-3 columns)
- Tablet: 2 columns or single column
- Mobile: full-width stack

### Navigation

- Desktop: persistent SideNav rail + expandable panel
- Tablet: collapsed rail, panel on demand
- Mobile: hidden entirely, hamburger > full-screen drawer

### Actions

- Desktop: visible buttons in header / row hover
- Mobile: overflow menu (three-dot) or FAB for primary action

## Touch Targets

When adapting for tablet/mobile:
- Minimum touch target: 44px height
- Button minimum: 40px (Small) — meets threshold
- Icon buttons: 44px tap area even if visual is smaller
- List items: 48px row height minimum on mobile

## Do / Don't

- Do: design desktop-first, then verify tablet/mobile works
- Don't: hide critical functionality on smaller screens
- Do: use column priority for tables instead of horizontal scroll
- Don't: rely on hover states for mobile (no hover on touch)
- Do: test at 980px (our md breakpoint) — many users have this resolution
- Don't: assume 1024px is a safe "desktop" width (our sidebar eats space)
- Do: provide the same data access on all breakpoints (different presentation, same info)

## Implementation

**Breakpoints in code:** `@reviewpro/js-browser/themes/ui-app.ts` > `breakpoints`
**MUI responsive:** use `useMediaQuery` hook or `Hidden` / `HiddenSSR` components
**Grid:** MUI Grid or CSS Grid — both available
