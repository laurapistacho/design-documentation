11:T12ee,# Error Handling

How errors are communicated to users across the platform. Different error types use different components and patterns.

## Error Types & Components

| Error Type | Component | Persistence | Scope |
|------------|-----------|-------------|-------|
| Field validation | Helper text (red) | Until fixed | Single field |
| Form submission failure | Alert (Error) | Until dismissed/fixed | Form-level |
| API / network error | Alert (Error) or Toast | Auto-dismiss or persistent | Page-level |
| Permission denied | Alert (Warning) + disabled UI | Persistent | Section |
| Not found (404) | Full-page empty state | Until navigation | Page |
| Server error (500) | Full-page error state | Until retry | Page |
| Action failure | Toast (Error) | Auto-dismiss (3s) | Global |
| Action success | Toast (Success) | Auto-dismiss (3s) | Global |

## Field Validation Errors

**Visual:** Red border (#D3000C) + red helper text (#B0000A)
**Timing:** On blur (leave field) or on submit
**Behavior:** Focus scrolls to first error field

```
[Label]
[Input field ─── red border]
⚠ Email address is required
```

Rules:
- Show one error at a time per field (most critical first)
- Clear error when user starts correcting (on change)
- Don't prevent typing while in error state

## Form-Level Errors

**Visual:** Alert component (Error variant) above the form or below the header
**When:** Server rejects the submission, cross-field validation fails

```
┌──────────────────────────────────────┐
│ ⚠ Unable to save changes            │
│ The email address is already in use. │
│                         [Try again]  │
└──────────────────────────────────────┘
```

Rules:
- Place above the form content, below the title
- Include a specific message (not "Something went wrong")
- Provide a retry action if applicable
- Persists until dismissed or form is re-submitted successfully

## Toast Notifications

**Visual:** Snackbar/Toast at bottom-center or bottom-right
**Duration:** Auto-dismiss after 3 seconds (error toasts: 5 seconds)
**When:** After an action completes (success or failure)

| Outcome | Toast variant | Duration |
|---------|--------------|----------|
| Success | Success (green) | 3s |
| Warning | Warning (yellow) | 5s |
| Error | Error (red) | 5s + "Retry" action |
| Info | Info (blue) | 3s |

Rules:
- One toast at a time (queue if multiple)
- Include an undo/retry action when possible
- Don't use toasts for validation errors (those belong on the field)

## Page-Level Errors

**Visual:** Full content area replacement (Perkins/Placeholder pattern)
**When:** The entire page data fails to load

```
        [Error illustration]
      Unable to load reviews

  We couldn't connect to the server.
  Check your connection and try again.

            [Retry]
```

Rules:
- Keep the navigation shell visible (TopNav + SideNav)
- Provide a Retry button
- If the error persists after retry, suggest contacting support

## Network / Connectivity

**Visual:** Alert bar (warning) at the top of the content area
**When:** Detected offline state or repeated API failures

```
┌──────────────────────────────────────┐
│ ⚠ Connection issue — some data may  │
│   be outdated.          [Refresh]    │
└──────────────────────────────────────┘
```

## Error Message Writing

| Principle | Example |
|-----------|---------|
| Be specific | "Survey name must be unique" not "Invalid input" |
| State what to do | "Enter a valid email address" not "Invalid email" |
| Don't blame | "Couldn't save" not "You made an error" |
| Be concise | One sentence, no period at end |
| Use sentence case | "Email is required" not "EMAIL IS REQUIRED" |

## Do / Don't

- Do: show errors as close to their source as possible (field > form > page)
- Don't: use only red color to indicate errors (add icon + text for accessibility)
- Do: provide a clear recovery action (retry, fix field, contact support)
- Don't: show technical error codes to users (log them, show human message)
- Do: preserve user input when an error occurs
- Don't: clear forms after a failed submission
- Do: stack error feedback (field error + form alert can coexist)
- Don't: show a generic "Something went wrong" without context

## Implementation

**Field errors:** `Helper-text` component in Error state + `FieldState` Error border
**Alerts:** `@reviewpro/ui-components` > `Alert` (Error variant)
**Toasts:** `@reviewpro/ui-components` > `Toast`, `Snackbar`
**Empty states:** `@reviewpro/ui-components` > `Placeholder` family
