11:T111f,# Form Patterns

How input forms are structured, validated, and submitted across the ReviewPro platform.

## Form Layouts

### Single Column (Default)

Standard vertical stack. Used for settings pages, creation dialogs, and configuration.

```
[Label]
[Input field (full width)]
[Helper text]

[Label]
[Input field (full width)]

[Label]
[Textarea]

---
[Cancel]  [Save]
```

### Two Column

Side-by-side fields for related inputs (first/last name, start/end date).
Collapses to single column on mobile.

```
[Label]          [Label]
[Field (50%)]    [Field (50%)]

[Label]
[Field (full width)]
```

### Inline Edit

Fields embedded in a table row or card. No separate form container.
Save/Cancel appear on the row level or as a floating toolbar.

### Stepped Form (Wizard)

Multi-step process with a ProgressBar above. Used for complex creation flows
(survey builder, digital stay configuration).

```
[Progress Bar: Step 1 / Step 2 / Step 3]

[Step content — single-column form]

[Back]  [Next / Finish]
```

## Field Sizing

| Context | Size | Reasoning |
|---------|------|-----------|
| Standalone form (dialog, page) | Large (48px) | Comfortable, spacious |
| Table inline edit | Small (36px) | Matches row height |
| Filter bar | Small (36px) | Compact, secondary to content |
| Settings page | Large (48px) | Primary editing context |

Rule: don't mix Large and Small in the same form.

## Validation Pattern

### When to Validate

| Trigger | What to Check |
|---------|---------------|
| On blur (field loses focus) | Required, format, min/max length |
| On submit | All fields, cross-field dependencies |
| On input (live) | Only for search/filter — never for form fields |

### Validation States

| State | Visual | Helper Text |
|-------|--------|-------------|
| Default | Gray border (#777777) | Guidance text (optional) |
| Error | Red border (#D3000C) + red helper | What went wrong + how to fix |
| Warning | Yellow border (#C28A29) + yellow helper | Non-blocking issue |
| Success | No special state (field returns to default) | — |

### Error Messages

- Write in sentence case, no period
- State what's wrong: "Email address is required"
- Don't blame the user: "Invalid email" > "You entered an invalid email"
- Be specific: "Must be at least 8 characters" > "Too short"

## Form Actions

### Placement

- **Dialog forms:** Footer row, right-aligned. Primary rightmost.
- **Page forms:** Sticky footer bar or inline at form bottom.
- **Inline edit:** Row-level save/cancel or floating toolbar.

### Button Pattern

| Action | Button Style | Position |
|--------|-------------|----------|
| Submit/Save | Primary Filled | Rightmost |
| Cancel/Dismiss | Outlined | Left of primary |
| Delete/Danger | Danger Filled | Leftmost (separated) |
| Secondary action | Ghost | Left side |

### Save Behavior

1. Validate all fields
2. If errors: scroll to first error field, focus it, show error states
3. If valid: submit > show loading state on button > on success: Toast + navigate/close
4. On server error: show Alert above form with retry option

## Spacing

| Element | Gap |
|---------|-----|
| Label to field | 4px (xs) |
| Field to helper text | 4px (xs) |
| Between field groups | 24px (xl) |
| Between related fields (same group) | 16px (lg) |
| Form to action buttons | 24px (xl) with divider above |

## Auto-save vs. Explicit Save

| Context | Pattern |
|---------|---------|
| Settings toggles (switch) | Auto-save + Toast confirmation |
| Configuration forms | Explicit Save button |
| Inline table edit | Save per row or batch save |
| Filters | Apply immediately (no save button) |

## Do / Don't

- Do: always provide a clear "Save" action (except auto-save contexts)
- Don't: disable the submit button while fields are empty (let validation guide)
- Do: preserve form state on accidental navigation (confirm discard dialog)
- Don't: clear the form on validation error (keep user input)
- Do: group related fields with visual proximity or a section title
- Don't: use more than one form per page unless they're independent sections
- Do: mark optional fields as "(optional)" rather than marking required ones
