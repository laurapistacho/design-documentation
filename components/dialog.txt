11:Tafa,# Dialog

Dialogs are modal overlays that require user attention. They interrupt the flow to confirm decisions, collect input, or display critical information.

## Overview

### When to use
- Confirm destructive actions (delete, remove)
- Collect focused input (create, edit in context)
- Display critical information that requires acknowledgment
- Multi-step flows that shouldn't navigate away

### When not to use
- Non-blocking information (use Alert or Toast)
- Complex forms with many fields (use a full page or Drawer)
- Contextual actions on a single item (use Popover or Menu)

## Variants (Device)

| Device | Behavior |
|--------|----------|
| Desktop | Centered modal with backdrop overlay |
| Mobile | Bottom sheet, slides up from bottom |

## Anatomy

1. **Backdrop** — semi-transparent overlay, closes on click
2. **Container** — white surface, border-radius: m (12px), shadow-m
3. **Title** — h6 style, top-left
4. **Close button** — IconButton, top-right
5. **Description** (optional) — body2 text below title
6. **Alert slot** (optional) — for inline warnings/info
7. **Content area** — scrollable if overflow
8. **Footer actions** — right-aligned buttons (primary rightmost)

## States

| State | Border |
|-------|--------|
| Default | No border highlight |
| Error | Red border on container (#D3000C) |

## Footer Actions Pattern

- Right-aligned, primary action rightmost
- Cancel/dismiss = Outlined button (left)
- Confirm/submit = Filled button (right)
- Danger action = Danger Filled button (right)
- Maximum 3 actions visible (more = rethink the flow)
- Optional left-aligned action (e.g., "Don't show again")

## Sizing

| Context | Width |
|---------|-------|
| Small dialog | 400px |
| Standard dialog | 560px |
| Large dialog | 720px |
| Mobile | Full width - 32px margin |

## Do / Don't

- Do: use a clear title that describes the decision ("Delete this review?")
- Don't: use generic titles ("Are you sure?")
- Do: make the primary action label specific ("Delete review", not "OK")
- Don't: nest dialogs inside dialogs
- Do: close on Escape key and backdrop click
- Don't: prevent dismissal unless data loss would occur (unsaved form)
- Do: keep content concise — dialogs are for focused decisions

## Accessibility

- Focus trap inside the dialog while open
- Return focus to trigger element on close
- `aria-modal="true"` and proper `role="dialog"`
- Escape key dismisses

- Alert — inline, non-modal feedback
- Popover — contextual, non-modal, attached to trigger
